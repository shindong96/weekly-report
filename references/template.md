# 출력 템플릿

카테고리는 `config.json`의 `categories` 순서·이모지·이름을 그대로 쓴다. 백틱 헤더를 바꾸지 않는다.
**내용이 없는 카테고리는 헤더째 삭제한다.** 아래는 카테고리 3개짜리 예시이며,
실제 출력에는 그 주에 작업이 있는 카테고리만 남긴다.

```
`금주업무`
🚀 **서비스 A 출시**

* [상태이모지] [작업 제목]
   * [왜 — 사용자·운영에 어떤 문제가 있었는가, 1문장. 제목으로 충분하면 생략]
   * [무엇을 했는가 — 1문장, 존댓말]
   * [지금 상태와 다음 단계 — 1문장]

🧪 **서비스 B 개선**

*  

➕ **그 외 업무**

*  

`차주업무`
🚀 **서비스 A 출시**

* [예정 작업 제목]
   * [무엇을 이어서 할 예정인지 — 1문장]

➕ **그 외 업무**

*  
```

## 상태 이모지

| 이모지 | 의미 | 판별 기준 |
|---|---|---|
| 🟢 | 완료 / 공유됨 | 해당 작업의 PR이 있거나 브랜치를 푸시함. Notion 상태는 보지 않음 |
| 🟠 | 진행 중 | 로컬 커밋·작업중 변경만 있거나, Notion Action에만 있고 코드가 없음 |
| ❌ | 미뤄짐 / 취소 | Git에 안 잡히므로 사용자가 알려줄 때만. 이유 1문장 + 미뤄진 항목은 3단계 불릿 |

차주업무에는 상태 이모지를 붙이지 않는다.

## 링크

기본적으로 달지 않는다. PR·Action·설계 문서는 개발자용이라 읽는 사람에게 의미가 없다.
회의 결과 정리, 이슈 분석 보고처럼 **읽는 사람이 열어봐야 할 공유물**에만, 무엇인지 한 단어로 붙인다:

```
* 🟢 보호자 동의 정책 논의 [(회의 결과)](https://...)
```

## 문체

- 존댓말 "~습니다"체
- 1단계 불릿은 짧은 명사구, 2단계 불릿이 설명
- 2단계 불릿은 한 불릿에 한 문장. 두 문장을 한 불릿에 이어 붙이지 않는다
- 2단계 불릿 순서는 왜 → 무엇 → 어디까지. "왜"는 사용자·운영 관점으로만, 코드 설명 금지
- 한 작업에 여러 결과가 있으면 2단계 불릿을 여러 개 쓴다 (최대 3개)
- 여러 항목을 나열할 때는 문장 안에 쉼표로 늘어놓지 말고 3단계 불릿으로 내린다
- Git에서 확인할 수 없는 수치나 배경은 지어내지 말고 `[확인 필요]`로 남긴다
